## 1. 프로젝트 목표 · 제품 개념

기획자·현업이 **캔버스에 화면을 대충 그리면**, 도구가 **규칙에 따라 사내 UI 표준으로 정리한 화면 초안과 코드(WebSquare XML)** 를 만들어 준다. 1개월 안에 동작하는 형태로 구현한다.

핵심 가치:
1. **직접 편집 가능한 캔버스** — 요소를 클릭해서 놓고, 드래그·리사이즈·정렬하고, 문구/필수 여부/항목/그룹을 바로 고친다.
2. **화면 생성** — "화면 생성" 클릭 시 캔버스 payload 를 백엔드로 보내 규칙 기반으로 변환.
3. **결과 출력** — 정리된 화면 Preview + WebSquare XML + 전달 데이터(JSON)를 확인·복사·다운로드.

작업 구분: **신규화면**(화면 유형 템플릿에서 시작) / **변경화면**(기존 화면을 불러와 수정).
대상 화면 유형: **목록 조회 / 상세 조회 / 등록·수정 / 팝업 / 메인 / 빈 화면**.
대상 시스템: 하이포탈 / 영업포탈 / 하이콜 (PoC 범위) — 계속 추가되므로 **검색형 콤보박스**로 선택.

PoC 성공 판정: 위 3가지가 화면 유형별로 재현되고 §11 수락 기준을 만족하면 1차 목표 달성.

## 2. 사용자 흐름

① 시스템 선택 (검색형 콤보박스)
② 작업 구분 선택 (신규 화면 / 변경 화면)
③ 신규: 화면 유형 선택 → 템플릿 프리셋이 캔버스에 로드 (빈 화면은 빈 상태)
   변경: 변경할 화면 선택 → 해당 화면의 기존 배치를 캔버스에 로드
④ 캔버스 편집
   - 좌측 팔레트에서 요소 클릭 → 캔버스에 배치 (16종: 제목/글자/입력칸/선택/라디오/날짜/체크/긴 글/파일/표/페이지/탭/이미지/버튼/구분선/묶음)
   - 드래그 이동, 8방향 리사이즈, 정렬 스냅 가이드, 겹침 순서
   - 다중 선택(Shift+클릭 / 빈 곳 드래그), 정렬·균등 분배, 그룹화(Ctrl+G), 우클릭 메뉴
   - 요소 1개 선택: 문구·항목·필수(＊) 편집 / 2개+ : 정렬·분배·그룹
   - 단축키: Ctrl+Z/Y, Ctrl+C/V, Ctrl+D, Ctrl+A, Ctrl+G, Del, Esc, 방향키(1px / Shift 10px)
   - 하단 툴바: 되돌리기/다시(60), 확대·축소(50~150%), 전체 비우기, 단축키 도움말(?)
   - 좌측 하단 "이미지 추가" — 이미지 파일을 드래그·선택·붙여넣기(Ctrl+V) → 캔버스에 `image` 요소로 배치(리사이즈 가능). data URL 로 payload `shapes[].src` 에 포함
⑤ "화면 생성" 클릭 → 캔버스 payload 를 `/api/generate` 로 전송 → 규칙 기반 변환
⑥ 결과 모달
   - [화면] 탭: 생성된 화면 Preview (iframe). 보기 전환 **결과 / 동시 보기**(내 스케치 ↔ 결과)
   - [전달 데이터] 탭: 백엔드로 보낸 payload(JSON)
   - [WebSquare XML] 탭: 생성된 XML (구문 강조)
   - 이미지 복사 / 내려받기 (파일 1개 → 단일 파일, 2개↑ → zip)
⑦ 수정하려면 캔버스로 돌아가 편집 후 다시 ⑤

## 4. 아키텍처

### 4.1 구성

- **프론트엔드(에디터)**: 예시를 계승한 단일 페이지 앱. 바닐라 JS(빌드 없음), 모듈 분리 허용. (§12 OI-2)
- **백엔드**: Node.js + Express. `/api/generate` 요청을 검증하고 규칙 기반 변환기를 호출한다.
- **규칙 기반 변환기**: `src/pipeline/deterministic.js`. 외부 호출·추론 없음.
- **메타 API**: 시스템·화면 목록. PoC 는 `fixtures/` 기반 (§12 OI-11, OI-12).

### 4.2 변환 규칙 (`src/pipeline/deterministic.js`)

입력 payload → 다음을 순서대로 수행:

1. **읽기 순서 정렬** — 요소를 위→아래, 같은 줄이면 왼→오른쪽으로 정렬.
2. **필수(＊) 전파** — `required` 인 label 옆(같은 줄 오른쪽, 없으면 바로 아래)의 입력 필드에 `required` 를 옮기고 `catalog/websquare/mapping.json` 의 `requiredClass` 로 출력.
3. **area 중첩** — `area` 박스 안(중심 기준)에 들어온 요소를 `<w2:group>...</w2:group>` 자식으로 중첩. 중첩 area(섹션)도 처리.
4. **태그 변환** — 요소 타입 → `catalog/websquare/mapping.json` 의 WebSquare 태그. select/radio → `<option>`, list → `<w2:gridColumn>`, tab → `<w2:tabItem>` 로 `items` 를 펼침.
5. **Preview HTML** — 좌표를 그대로 보존한 와이어프레임. (정렬·표준 스타일 적용은 하지 않음 — "배치 그대로")

**하지 않는 것**: 자연어 해석, 질문 생성, 레이아웃 유형 인식(조회영역/결과영역 등), 토큰 스타일 적용, 자동 검증 재수정 루프.

### 4.3 프로젝트 구조

```
src/
  server/    index.js, routes/{generate,meta}.js, fixtures.js
  pipeline/  deterministic.js
  shared/    validate.js, constants.js, paths.js
  web/       index.html, styles.css, js/{main,editor,combobox,templates,result-modal,api,constants,highlight,toast}.js, smoke.html
schemas/     screen-draft.schema.json, generation-result.schema.json
fixtures/    systems.json, screens/{portal,salesportal,hicall}.json, payloads/{list,sample}.json
catalog/     components.json, tokens.json, layout-guide.md, websquare/mapping.json
config/      settings.json
runs/        평가 산출물 (gitignore)
```

## 5. 역할 분담 (2인)

### 5.1 백엔드 — 서버 · 변환기 · 카탈로그

- `src/server/` — 라우트, 요청 검증, 정적 서빙
- `src/pipeline/deterministic.js` — 변환 규칙 (§4.2). 매핑 정합성·유형별 패턴 보강
- `catalog/` — `mapping.json` 의 `requiredClass` 등 명칭을 사내 WebSquare 표준으로 확정, `componentKey`/`tokenKey` 정합
- 메타 데이터 소스 — PoC 는 `fixtures/`, 실 연동은 정식 개발 과제(OI-11, OI-12)
- 인수인계 상세: [`04_백엔드_인수인계.md`](04_백엔드_인수인계.md)

### 5.2 프론트엔드 — UI / 캔버스 에디터

- `src/web/` 전체. 예시 UI 계승.
- 상세 작업: §8.2 (대부분 ✅ 완료)

### 5.3 인터페이스 계약

두 사람의 경계 = `schemas/` 의 JSON Schema 2종.
- `screen-draft.schema.json` — 프론트가 만드는 payload (§6.1)
- `generation-result.schema.json` — 백엔드가 돌려주는 결과 (§6.2)

**필드 추가는 무해(무시됨). 기존 필드 제거·의미 변경·enum 축소는 상대에게 공유 후 양쪽 동시 수정.** 변경 시 PR + 상호 리뷰 + `test/schemas.test.js` 갱신.

### 5.4 병행 개발 전략

- 프론트는 `fixtures/results` 없이도 `deterministic.js` 를 직접 호출하는 서버로 확인 가능.
- 백엔드는 `fixtures/payloads/*.json` 으로 변환기를 단독 검증.
- `scripts/run-eval.mjs` 가 두 쪽을 잇는 회귀 기준.

## 6. 데이터 계약 상세

정본은 `schemas/*.json`. 아래는 형태 기준.

### 6.1 화면정의 payload (프론트 → 백엔드) — `screen-draft.schema.json`

```jsonc
{
  "systemId": "portal",                             // /api/systems 의 id
  "systemName": "하이포탈",                          // 표시용
  "mode": "new | edit",
  "template": "list | detail | form | popup | main | blank", // mode=new 일 때만
  "baseScreen": { "id": "SCR-P-LIST-01", "name": "계약 조회화면" },   // mode=edit 일 때 필수
  "screenName": "계약 조회",
  "canvas": { "w": 960, "h": 600 },
  "shapes": [
    {
      "id": "s1",
      "type": "title|label|input|select|radio|date|check|text|file|list|pager|tab|image|button|divider|area",
      "x": 30, "y": 52, "w": 170, "h": 28,
      "label": "성명",              // optional
      "items": "자녀,배우자,사위",   // optional, list/select/radio/tab 의 컬럼·옵션(쉼표 구분)
      "required": true,             // optional
      "group": "g2",                // optional, 같은 값 = 한 그룹(에디터에서 함께 이동)
      "src": "data:image/png;base64,..."  // optional, type=image 일 때 이미지 data URL
    }
  ]
}
```

### 6.2 생성결과 (백엔드 → 프론트) — `generation-result.schema.json`

```jsonc
{
  "status": "ok | error",
  "preview": { "html": "<!DOCTYPE html>..." },       // [화면] 탭 (자기완결형, iframe srcdoc)
  "code": {
    "websquareXml": "<w2:group ...>...",              // [WebSquare XML] 탭
    "files": [ { "path": "screen.xml", "content": "..." } ]   // 내려받기 (2개↑ → zip)
  },
  "report": {
    "converter": "deterministic",
    "elapsedMs": 3,
    "propagatedRequired": 2,        // 필수(＊) 라벨 → 필드로 자동 전파된 건수
    "unresolved": [],
    "note": "외부 LLM 미사용 — 규칙 기반 변환 결과입니다."
  },
  "error": { "message": "...", "log": "..." }         // status=error 시
}
```

### 6.3 메타 API (백엔드 → 프론트)

```jsonc
// GET /api/systems
{ "systems": [ { "id": "portal", "name": "하이포탈", "sub": "그룹 포탈" }, ... ] }

// GET /api/screens?system=portal&q=계약   (변경화면 콤보박스, q = 타입어헤드 검색어)
{ "screens": [ { "id": "SCR-P-LIST-01", "name": "계약 조회화면", "template": "list", "systemId": "portal" } ] }

// GET /api/screens/SCR-P-LIST-01   (기존 화면 정의 → 캔버스 로드)
{ "id": "SCR-P-LIST-01", "name": "계약 조회화면", "systemId": "portal", "template": "list",
  "canvas": { "w": 960, "h": 600 }, "shapes": [ /* 6.1 shapes 형식 */ ] }
```

### 6.4 이미지 첨부

별도 API 없음. 에디터에서 이미지를 드래그·선택·붙여넣기 하면 클라이언트가 긴 변 ≤1400px 로 축소해 **data URL** 로 인코딩하고, 캔버스에 `type:"image"` shape (`src` = data URL) 로 배치한다. payload·저장본에 그대로 포함된다. 서버 저장 없음.

## 7. 컴포넌트 ↔ 사내 표준(WebSquare) 매핑

`src/pipeline/deterministic.js` 의 기준. 상세·시스템별 차이는 `catalog/websquare/mapping.json` (+ `override.<systemId>.json`).

| 팔레트 요소 | 의미 | WebSquare (기준) | 비고 |
|---|---|---|---|
| 입력칸 `input` | 텍스트 입력 | `<w2:inputBox>` | 필수 시 `class="w2input_essential"` |
| 선택 `select` | 드롭다운 | `<w2:selectBox dataList="...">` + `<option>` | 필수 시 `w2selectbox_essential` |
| 라디오 `radio` | 라디오 그룹 | `<w2:radiobutton dataList="...">` + `<option>` | `items` → 옵션 |
| 날짜 `date` | 날짜 선택 | `<w2:calendar displayFormat="yyyy-MM-dd">` | |
| 체크 `check` | 체크박스 | `<w2:checkbox label="...">` | |
| 긴 글 `text` | 여러 줄 입력 | `<w2:textarea>` | 필수 시 `w2textarea_essential` |
| 파일 `file` | 파일 업로드 필드 | `<w2:fileUpload>` | 화면 안의 업로드 컴포넌트 |
| 표 `list` | 그리드 | `<w2:gridView>` + `<w2:gridColumn>` × n | `items` → 컬럼 |
| 페이지 `pager` | 페이지네이션 | `<w2:pagination>` | |
| 탭 `tab` | 탭 컨트롤 | `<w2:tabControl>` + `<w2:tabItem>` × n | `items` → 탭 이름 |
| 이미지 `image` | 이미지/아이콘 | `<w2:image alt="..." [src="..."]>` | 캔버스에 실제 이미지가 있으면 `src` = data URL |
| 버튼 `button` | 실행 | `<w2:trigger value="..." onclick="fn_...">` | |
| 구분선 `divider` | 가로 구분선 | `<w2:group class="w2group_divider">` | |
| 글자 `label` | 항목명 | `<w2:textbox>` | |
| 제목 `title` | 섹션 제목 | `<w2:textbox>` | |
| 묶음 `area` | 레이아웃 그룹 | `<w2:group>` | 안의 요소를 자식으로 중첩 |

- `requiredClass` 명칭은 관례적 추정값 — **사내 WebSquare 표준으로 확정 필요** (백엔드).
- 매핑에 없는 타입은 `<!-- type (매핑 정의 없음) -->` 주석으로 표시.

## 9. 제약사항 · 보안

### 9.1 기술
- **외부 LLM(상용 AI API) 사용 금지.** 자체 모델·호스팅도 없음. 전부 규칙 기반.
- **생성 코드 타겟은 WebSquare XML 로 고정.** Preview HTML 은 화면 확인용.
- Preview HTML 은 최신 Chrome/Edge 에서 추가 빌드 없이 렌더 (자기완결형).
- 에디터는 빌드 없이 동작 (바닐라 JS).

### 9.2 데이터 · 보안
- **사내 자산 반입 금지** — 영업포탈 샘플 코드/이미지 반입하지 않는다. WebSquare 스키마·샘플은 외부 공개 자료 기준 (OI-3).
- 사내 UI 표준 카탈로그는 PoC 용 최소 범위만 별도 정리.
- 입력 캔버스·이미지에 사내 기밀/개인정보 포함 금지 — 에디터에 가이드 문구 표시.
- `.env` 는 `PORT` 만. 입력·산출물은 로컬/PoC 환경 내에서만 취급.

### 9.3 가정
- 대상 화면 유형별 참조 자료가 확보된다.
- WebSquare 매핑 최소 세트를 PoC 기간 내 정의 가능하다.
