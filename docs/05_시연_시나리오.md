# 하이스케치 PoC — 시연 시나리오

| 항목 | 내용 |
|---|---|
| 대상 | 기획/PM/이해관계자 대상 데모 (10~15분) |
| 준비물 | `데모실행.bat`, 크롬(또는 엣지) |
| 관련 | [개발지시서](01_개발지시서.md), [평가](03_평가결과.md), [백엔드 인수인계](04_백엔드_인수인계.md) |

> **핵심 메시지**: "러프하게 그린 화면 스케치 → **규칙에 따라** 사내 표준 WebSquare 화면·코드로 변환."
> 외부 LLM(상용 AI)은 쓰지 않는다. 규칙 기반이라 **같은 입력이면 항상 같은 결과**가 나온다.

---

## 0. 시연 5분 전 준비

1. `데모실행.bat` 더블클릭 → 검은 창에 `하이스케치 → http://localhost:3000`, 브라우저 자동 오픈
2. 화면이 예전 테스트 상태로 열리면 상단 **비우기** 클릭, 왼쪽에서 시스템·유형 다시 선택 (또는 새로고침)
3. 브라우저 확대(Ctrl + `+`) 1~2단계 — 뒤에서도 보이게
4. 예행 1회: 유형 **등록·수정** → **화면 생성** → 모달 3탭 확인 → 닫기 → **비우기**

---

## 1. 문제 제기 — 30초 (말로)

- WebSquare 화면 1개를 편집기에서 직접 만들면 통상 **25~40분** (레이아웃, 표준 컴포넌트, 필수·정렬 규칙).
- 기획자의 스케치는 빠르지만 그걸 개발 표준으로 옮기는 게 병목.
- 이 PoC: **캔버스에 러프하게 그린다 → 규칙 기반 변환기가 사내 표준 태그로 정리한다 → WebSquare XML 까지 뽑는다.**

---

## 2. 에디터로 화면 그리기 — 4분

> "먼저 기획자가 화면을 그리는 부분입니다."

| 순서 | 할 것 | 말할 것 |
|---|---|---|
| 2-1 | 왼쪽 **시스템** = 하이포탈 선택 (검색 가능) | "대상 시스템을 고릅니다. 시스템별 표준 차이를 대비해 먼저 선택." |
| 2-2 | **신규 화면** → 유형 **등록 · 수정** 클릭 | "새 화면이면 유형을 고르면 기본 골격이 깔립니다. (변경 화면이면 기존 화면을 불러와 수정)" |
| 2-3 | 왼쪽 팔레트에서 **입력칸 / 선택 / 날짜** 클릭 → 캔버스에 배치 | "요소는 클릭하면 놓입니다. 16종." |
| 2-4 | 요소를 **드래그로 이동**, **모서리 점으로 크기 조절** — 분홍 스냅 가이드 | "반듯하게 안 그려도 됩니다." |
| 2-5 | 요소 클릭 → **플로팅 툴바**에서 문구 입력, **＊(필수)** 토글 | "라벨·필수 여부·항목을 여기서 바로 고칩니다." |
| 2-6 | 요소 2개 **Shift+클릭** → 툴바에서 **왼쪽 정렬**, (3개+) **균등 분배** | "여러 개 선택하면 정렬·분배." |
| 2-7 | 2개 선택 → **Ctrl+G**(그룹) → 드래그하면 같이 이동 → **Ctrl+Shift+G** 해제 | "묶어서 다루려면 그룹." |
| 2-8 | 요소에서 **우클릭** → 복제 / 삭제 메뉴 | |
| 2-9 | **Ctrl+Z**(되돌리기), 하단 **줌**, 우하단 **?**(단축키 도움말) | "60단계 되돌리기, 확대·축소, 단축키 안내." |
| 2-10 | 상단 화면 이름칸에 **"계약자 등록"** 입력 | "신규 모드는 이름 직접 입력. 변경 모드면 불러온 이름 고정." |

> 상단 "저장됨" 자동 저장 표시를 짚어주면 좋음 — 새로고침해도 유지.

## 3. 화면 생성 — 3분 (하이라이트)

| 순서 | 할 것 | 말할 것 |
|---|---|---|
| 3-1 | 왼쪽 아래 **보충 설명(메모)**에 입력: `주민번호는 필수` 등 | "그림으로 표현 못 하는 규칙은 메모로 남깁니다. **전달 데이터에 함께 담겨** 개발자에게 전달됩니다. (변환기가 자동 반영하진 않습니다.)" |
| 3-2 | 참고 파일(Excel·PPT·이미지) 첨부 가능함을 언급 (드롭존) | "화면정의서도 붙여서 전달." |
| 3-3 | 상단 **화면 생성** 클릭 → 진행 단계 표시 | "payload 가 서버로 갑니다. 스키마 검증 → 규칙 기반 변환." |
| 3-4 | 결과 모달 **[화면]** 탭 — 미리보기 | "그린 대로 화면이 나옵니다." |
| 3-5 | 상단 **동시 보기** 전환 — 내 스케치 ↔ 생성 결과 나란히 | "왼쪽 내가 그린 것, 오른쪽 변환 결과. 변경 전후 비교." |
| 3-6 | **[전달 데이터]** 탭 | "기획자 화면 → 백엔드로 넘어가는 데이터. 프론트↔백엔드 계약(JSON 스키마)입니다." |
| 3-7 | **[WebSquare XML]** 탭 — 구문 강조 | "표준 컴포넌트로 변환된 코드. **`area` 안 요소가 `<w2:group>` 로 묶이고, 필수 항목엔 essential 클래스가 자동으로 붙습니다.**" |
| 3-8 | 상단 **이미지 복사** / **↓ 내려받기** | "화면은 이미지로 클립보드에, 코드는 파일로. (파일 여러 개면 zip)" |
| 3-9 | 하단 상태줄: **"✓ 변환 완료 (규칙 기반) · 필수 표시 N건 자동 반영"** 짚기 | "규칙 기반이라 **자연어 규칙 해석·레이아웃 유형 자동 정렬은 하지 않습니다.** 배치를 그대로 표준 태그로 옮기고, 필수 표시·묶음 중첩 같은 기계적으로 확실한 것만 반영합니다. 나머지 정렬·스타일은 사용자가 후수정. (규칙 보강은 후속 과제)" |

## 6. 정리 — 1분 (말로)

- **완성**: 캔버스 에디터 전체, 프론트↔백엔드 데이터 계약(스키마), 결과 모달, 규칙 기반 변환기, 반응형·접근성, 평가, 테스트·CI.
- **모델**: "골격 자동 생성 + 사용자 후수정". 규칙 기반이라 예측 가능·재현 가능·오프라인.
- **후속**: 변환 규칙 보강(화면 유형 패턴 인식, 토큰 스타일, 버튼 정렬) → 후수정 분량 축소 (`docs/03` §6, `docs/04` A-3b).

## 부록 A. 예상 질문 대응

| 질문 | 답 |
|---|---|
| AI(LLM)를 쓰나요? | **아니오.** 외부 상용 AI API 사용 불가 방침. 전부 정해진 규칙으로 변환합니다. 그래서 결과가 항상 동일하고 예측 가능합니다. |
| 그럼 "정리"는 어디까지? | 읽기 순서 정렬, 표준 태그 매핑, 필수(＊) 자동 표시, 묶음(`area`) 자식 중첩까지. 자연어 규칙 해석·레이아웃 유형별 자동 정렬은 안 합니다(후속 과제). |
| 실제 사내 WebSquare 표준 반영됐나요? | 외부 공개 자료 기준(OI-3). 컴포넌트 클래스명 등은 사내 표준으로 확정 필요 — `docs/04` 에 명시. |
| 왜 React가 아니고 바닐라 JS? | 빌드 없이 바로 뜨는 걸 우선(OI-2). 예시 프로토타입 계승. |
| 변경 화면(기존 화면 수정)도 되나요? | 됩니다. 시스템 선택 → 변경 화면 → 화면 검색 → 불러오면 기존 배치가 캔버스에. |
| 첨부(엑셀)는 어떻게 쓰이나요? | 현재는 payload 에 참조만 담아 개발자에게 전달. 텍스트·표 추출 반영은 후속(OI-8). |
| 생성 시간은? | 즉시(<0.01초). 서버 부담 없음. |

## 부록 B. 장애 대응

| 증상 | 조치 |
|---|---|
| 브라우저가 안 열림 | 주소창에 직접 `http://localhost:3000` |
| "포트가 이미 사용 중" / 서버가 안 뜸 | 이전에 열어둔 검은 창을 닫고 `데모실행.bat` 다시 실행 |
| 생성 결과가 이상함 | 모달 닫고 **비우기** → 다시. 또는 새로고침(자동 저장으로 복원) |
| 캔버스가 예전 상태 | 상단 **비우기**, 시스템·유형 다시 선택 |
| "Node.js not found" (검은 창) | 시연 PC에 Node.js LTS 설치 (https://nodejs.org) |
| 단축키가 안 먹음 | 캔버스를 한 번 클릭해 포커스를 준 뒤 다시 |

## 부록 C. 시연 안 하는 게 나은 것

- **XML을 실제 WebSquare에 붙여 실행** — 대상 버전·스키마 미확정(OI-3). "코드가 나온다"까지만.
- 실데이터 — 사내 기밀·개인정보 금지.
- 복잡한 자연어 규칙을 넣고 "이거 반영되나요?" — 반영 안 됩니다(설계상).
