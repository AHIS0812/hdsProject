## 3. 화면별 정성 평가 (SC-1 — 사용 가능한 초안인가)

> **결정론적 변환기 기준선**. O/△/X, 종합 4단계. AI 파이프라인 도입 후 갱신.

### 3.1 공통 관찰 (결정론적 변환기의 구조적 특성)

| 항목 | 관찰 |
|---|---|
| 컴포넌트 매핑 | **정확**. `input→w2:inputBox`, `date→w2:calendar`, `select→w2:selectBox`+`<option>`, `list→w2:gridView`+`w2:gridColumn`, `text→w2:textarea`, `button→w2:trigger`, `label/title→w2:textbox`. 8케이스 미매핑 0 |
| 텍스트 정확도 | **완벽**. 라벨·컬럼명이 입력한 그대로(기계적 복사). E-QUERY 담당자 컬럼 추가도 정확 반영 |
| XML well-formed | **OK**. 8케이스 전부 태그 균형, `<w2:group id="screenRoot">` 래핑, Preview HTML 렌더 가능 |
| 결정성 | **완벽**. 동일 입력 → byte-identical |
| 레이아웃 정리 | **부분**. `area` 안의 요소가 `<w2:group>...</w2:group>` 자식으로 **중첩됨**(N-LIST 조회영역 1, N-FORM 섹션 2, N-MAIN 카드 3, N-DETAIL 2). 좌표는 Preview 에 보존. **단** 정렬(버튼 우측)·조회/결과 영역의 "유형" 인식·섹션 간 순서 규칙은 여전히 미적용 |
| 필수(＊) 처리 | **반영됨**. 필수 라벨 → 같은 줄 오른쪽(없으면 바로 아래) 필드로 전파. N-FORM 3건(성명·구분·주민번호 → `w2input_essential`/`w2selectbox_essential`), N-LIST·N-DETAIL·N-BLANK 각 1건. `mapping.json` 의 `requiredClass` 로 출력 |
| 보충 설명(note) 반영 | **없음**. "주민번호 필수", "등록일 오늘 기본값", "버튼 활성화 조건" 등 자연어 규칙 전부 무시(해석기 없음) |
| 미확정 처리 | **질문 안 함**. 애매해도 변환만 수행 (`questions` 없음) — Stage A 의 역할 |
| 표준 준수 | **낮음**. raw `w2:*` 태그만, `componentKey`/`tokenKey`·토큰 스타일·버튼 역할색 없음 |

| 등록 · 수정 화면 | 30~50 | 스케치 4~8 + 생성 <0.1 + 수정 | 필수 표시 등 후수정 필요분이 큼(현 기준선) |
| 팝업 화면 | 15~25 | 스케치 2~4 + 생성 <0.1 + 수정 | 요소 적어 빠름 |

- 생성 자체 소요(`report.elapsedMs`): 결정론적 변환은 <10ms. AI 파이프라인 도입 시 autofix 포함 실측 필요(목표 §AC-13: 3분 이내).
- **1차 SC-3 판정**: 생성 지연은 병목이 아님을 확인. 총 소요의 관건은 "후수정 분량" → SC-1 품질에 좌우됨. 2차에서 실측.
