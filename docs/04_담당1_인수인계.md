## 2. 담당 1이 끼울 지점 (딱 한 군데)

`src/server/routes/generate.js`:

```js
function runPipeline(payload) {
  return mockResult(payload);   // ← 여기를 교체
}
```

권장 형태 (`src/pipeline/index.js` 새로 만들어 오케스트레이션):

```js
export async function runPipeline(payload, ctx) {
  const ir = await runStageA(payload, ctx);          // A-4
  if (ir.questions?.length && needsUser(ir)) {
    return { status: 'needs_input', questions: ir.questions, ir };
  }
  let out = await runStageB(ir, ctx);                // A-5
  const fixed = await autofix(out, { ...ctx, ir });  // A-6
  return {
    status: 'ok',
    preview: { html: fixed.output.previewHtml },
    code: { websquareXml: fixed.output.websquareXml, files: [...] },
    ir,
    report: { retries: fixed.retries, elapsedMs, fallbacksApplied, unresolved, usedDeterministicFallback: false },
  };
}
```

- `runPipeline` 이 **throw** 하거나 **`status:'error'`** 를 반환하면 라우트가 자동으로 `deterministicResult(payload, err.message)` 로 폴백한다 (이미 배선됨, AC-9).
- 그러니 파이프라인은 "성공 결과" 또는 "throw" 만 신경 쓰면 된다.
- `/api/refine` 도 같은 `runPipeline` 을 `req.body.basePayload` + `answers`/`instruction` 으로 호출하도록 되어 있음 (A-8).

`app.js` 에서 provider 주입:

```js
import { providersFromEnv } from '../llm/provider.js';
const ctx = { providers: providersFromEnv(), catalog: loadCatalog() };
```

## 3. 계약 (스키마) — 바꾸지 말 것

프론트엔드가 이 형태에 의존한다. 필드 추가는 가능(무시됨), **기존 필드 제거·의미 변경·enum 축소는 프론트 수정 없이는 금지**.

| 스키마 | 방향 | 프론트 의존 부분 |
|---|---|---|
| `schemas/screen-draft.schema.json` | 담당 2 → 담당 1 | 에디터가 생성. `type` enum 16종, `mode`/`template`/`baseScreen`, shape `x/y/w/h/label/items/required/group` |
| `schemas/generation-result.schema.json` | 담당 1 → 담당 2 | 결과 모달이 소비. **아래 3.1 참조** |
| `schemas/refine-request.schema.json` | 담당 2 → 담당 1 | `basePayload`(필수), `baseIr`/`answers`/`instruction`(선택) |
| `schemas/ir.schema.json` | 담당 1 내부 (Stage A→B) | 프론트 미의존. 담당 1 자유롭게 확장 가능(회귀 테스트용으로만 고정 권장) |

### 3.1 `generation-result` — 프론트가 실제로 읽는 필드

```jsonc
{
  "status": "ok" | "needs_input" | "error",   // 필수

  // status=ok 일 때
  "preview": { "html": "<!DOCTYPE html>..." },        // 결과 모달 [화면] 탭 iframe srcdoc
  "code": {
    "websquareXml": "<w2:group ...>",                 // [WebSquare XML] 탭 (구문 강조), 복사
    "files": [ { "path": "screen.xml", "content": "..." } ]  // 2개↑이면 내려받기가 zip
  },
  "ir": { ... },                                       // (선택) 표시 안 함, 회귀·refine 용

  // status=needs_input 일 때
  "questions": [
    { "id": "q1", "targetId": "s7", "question": "...", "options": ["A","B"] }  // options 없으면 자유 입력
  ],

  // status=error 일 때
  "error": { "message": "...", "log": "..." },         // <pre> 로 노출

  // 항상 (선택)
  "report": {
    "retries": 0, "elapsedMs": 1234,
    "fallbacksApplied": [], "unresolved": [],
    "usedDeterministicFallback": false                  // true 면 상태줄에 "결정론적 변환" 표기
  }
}
```

- `report.elapsedMs` 있으면 상태줄에 `· N초` 표시. 없고 `report.mock` 이면 `· mock`.
- `preview.html` 은 **자기완결형 HTML** (iframe `srcdoc` 에 그대로 들어감). 외부 리소스 로드 불가 전제.
- 질문 답변은 `/api/refine` 의 `answers: [{ questionId, value }]` 로 되돌아온다.

## 4. 파일별 할 일 (우선순위 순)

지시서 §8.3 대응. `[M]` 필수 / `[S]` 있으면 좋음.

1. **[M] A-2 · `src/llm/claude.js`** — `@anthropic-ai/sdk` 연동. `generateStructured({system,messages,images?,jsonSchema})` / `generateText(...)`. timeout·지수백오프·usage 로깅. 키는 `process.env.ANTHROPIC_API_KEY` 만.
2. **[M] A-4 · `src/pipeline/stageA.js`** — payload → IR. 러프 좌표 → 행/섹션/그리드 정리, `componentKey`/`tokenKey` 매핑(`catalog/`), 유형별 패턴(조회영역/결과영역 등, `catalog/layout-guide.md`), 미확정 → `questions[]`. `mode=edit` 시 `baseScreen` (`GET /api/screens/:id` 로 원본 shapes) 대비 변경분. payload shape 의 `group` 은 "묶어서 보라"는 힌트로 활용 가능.
3. **[M] A-5 · `src/pipeline/stageB.js`** — IR → WebSquare XML + Preview HTML + report. 표준 `componentKey` 우선, 토큰 스타일, 버튼 우측 정렬·역할색. 미사용 표준은 `report.fallbacksApplied`.
4. **[M] A-6 · `src/pipeline/autofix.js`** — XML well-formed + (가능 시) WebSquare 스키마 + HTML 렌더 sanity. 실패 → 검사 결과를 모델에 재입력, 최대 `AUTOFIX_MAX_RETRIES`(기본 3). 3회 후 실패면 throw (→ 라우트가 결정론적 폴백).
5. **[M] 오케스트레이션 · `src/pipeline/index.js` (신규)** — §2 참조. `routes/generate.js` 의 `runPipeline` 을 여기로 위임.
6. **[S] A-7 · 첨부 파싱** — 이미지(멀티모달), Excel/PPT(텍스트·표 추출, OI-8) → Stage A 컨텍스트. `payload.attachments[].url` = `/uploads/<uuid>.ext`.
7. **[S] A-9 · `runs/<timestamp>/`** — 생성 1건마다 `payload.json`·`ir.json`·`screen.xml`·`preview.html`·`report.json` 저장. `scripts/run-eval.mjs` 가 동일 포맷으로 저장하니 참고. (`runs/` 는 gitignore)
8. **[S] A-10 · 시스템별 카탈로그** — `catalog/websquare/override.<systemId>.json` (OI-4). 없으면 공통 `mapping.json`.
9. **[S] A-11 · provider A/B 비교** 1회 → `docs/01` §12 OI-1 기록.
10. **A-3 (결정론적 변환기) 보강** — 이미 1차 구현됨(`src/pipeline/deterministic.js`). 담당 1은: ① `mapping.json` 의 `requiredClass` 명칭을 **사내 WebSquare 표준으로 확정** (현재 `w2input_essential` 등은 관례적 추정), ② `componentKey`/`tokenKey` 추상화 레이어와 정합, ③ 유형별 패턴.

## 8. 주의사항

- **API 키**: `.env` 에서만. 프론트 번들·응답·로그에 절대 노출 금지 (AC-12). 현재 `src/web/` 에 키 참조 0건 — 유지.
- **사내 자산 반입 금지** (§10.2): WebSquare 스키마·샘플은 외부 공개 자료만. 확보 전까지 `mapping.json` 수준 매핑 사용 (OI-3).
- **실데이터 금지** (OI-7): 상용 LLM API 전송 데이터 범위·보관 정책 확인 전까지 실 화면정의 데이터 넣지 말 것.
- **커밋 규약**: 커밋 메시지 끝에 `Co-Authored-By: ...` (기존 규약 확인). 커밋/푸시는 요청 시.
- **스키마 변경 시**: 반드시 담당 2에 공유. `test/schemas.test.js` + 프론트 `toPayloadShapes`/결과 모달 동시 확인.
